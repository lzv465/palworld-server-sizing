## 配置按人数怎么选：槽位上限不等于同时在线

服务器设置里可以开 32 个槽位，不代表 32 个人同时在线时还能跑得动。规划配置要看三个不同的数字：游戏内人数上限、日常同时在线人数、活动期间的峰值在线人数。第三个才是选配置的依据。

第三方主机商 A5idc 在 2026 年 10 月发布过一份按玩家规模估算的区间表，可以作为初始选型参考。这不是官方硬性标准，也不代表某台机器的实测承载能力。

| 高峰同时在线 | CPU 初始参考 | 内存初始参考 | 注意事项 |
| --- | --- | --- | --- |
| 1–8 人 | 2–4 vCPU | 8–16 GB | 据点较多或有模组时靠区间上沿 |
| 9–16 人 | 4–6 vCPU | 16–24 GB | 关注持续 CPU 占用和存档增长 |
| 17–24 人 | 6–8 vCPU | 24–32 GB | 建议独占实例，确认资源配额 |
| 25–32 人 | 8 vCPU 及以上 | 32–48 GB | 对单核性能和网络要求更高，需压测 |
| 32 人以上 | 逐级增加 | 48 GB 起 | 不能只看表，要分阶段扩容 |

抬高负载的不只是人数。多个玩家同时建造、生产、在据点之间调度帕鲁，比分散挂机更吃资源；世界存档会随游玩时间、建筑数量增长，占用磁盘、拉长备份时间；模组和管理插件会额外吃内存，未加模组的估算不能直接套到模组服上。开服第一天的玩家数也不该当作三个月后的容量基准。

## 买完只是开始：备份、重启和端口安全

云主机开通只是第一步，帕鲁专用服务器需要自己用 SteamCMD 装，App ID 是 `2394010`。Evoxt 不提供游戏一键部署面板，这一点和国内的面板服不一样，也是它价格低的原因之一。装完之后，日常运维有几件事绕不开。

**存档备份。** Evoxt 自带每周异地备份，但游戏存档的粒度可能需要更细。开源工具 palworld-server-tool-enhanced 支持定时同步存档、自动备份和备份管理，运行时会解析 `Level.sav`，短时间占用约 1GB 到 3GB 内存。规划内存时要把这部分算进去，别让游戏进程把 16GB 吃满。

**定时重启。** 帕鲁服务端长时间运行后内存会缓慢增长。该工具支持每天、每隔数天、每周或每月自动平滑重启，也能用标准五段 Cron；到点时如果服务器已被管理员手动停服，本次计划会安全跳过。

**更新流程。** SteamCMD 更新要先保存世界、备份、平滑关服，再更新、重启。更新失败时应暂停守护，避免用不完整的文件反复启动。

**端口安全。** 游戏端口 8211 需要对外开放，但 REST API 端口 `8212` 和 RCON 端口 `25575` 不要直接暴露到公网。这两个端口一旦被扫到，等于把服务器管理权限交出去。管理面板本身也应该加一层身份验证，或者只允许本机访问。

这些都不是 Evoxt 自带的功能，需要自己部署。买之前把这块时间成本算进去，尤其是没有 Linux 经验的情况。

## 常见问题

**4 核 8G 够几个人？**
按第三方估算，1 到 8 人高峰、无模组、据点不密集的情况下够用。人数接近 8 人、建筑变多、或者加了模组，内存会先紧。这时候加 8GB 内存比换 CPU 更直接。

**月付还是年付？**
Evoxt 支持月付到 3 年预付，但官网没标年付折扣。第一次开服建议先月付，跑满一个活动周期看监控数据，确认配置合适再考虑长期预付。

**首月便宜，续费会不会涨？**
Evoxt 官网价格页展示的是月付价，没有区分首单价和续费价。下单前在订单页核对最终金额和计费周期就行。

**要不要直接买高配？**
不建议。先按高峰同时在线人数选一档，留出内存余量，跑两周看 CPU 是否长期超过 70% 到 80%、可用内存是否持续偏低、磁盘是否够更新和备份。有数据再扩容，比凭感觉买高配省一半钱。

**服务器卡是配置不够还是线路问题？**
先看资源：CPU 高峰长期 70% 到 80% 以上、内存吃满出现交换、磁盘剩余空间不足，都是配置信号。资源都富裕但只有晚高峰卡、并且伴随丢包和延迟抖动，那是线路问题，升级配置解决不了，换机房更有效。
